## 1. 目标与设计原则

设计一套在计算资源受限条件下运行的自主推棋算法。小车可获得：

- 前视 RGB 相机图像；
- 小车在场地坐标系中的绝对位置与朝向；
- 已完成标定的相机内参、畸变参数及相机相对车体的安装参数；
- 场地静态尺寸和己方得分区配置。

任务目标是在随机散落的 32 枚棋子中，尽可能多地将棋子推入己方得分区，并在有限比赛时间内提高净得分数量。

### 1.1 核心原则

1. **只运行一个神经网络：** YOLO 负责单类棋子检测。其余功能采用几何计算、传统视觉、数据关联、聚类、状态机、搜索和反馈控制实现。
2. **检测与决策分离：** YOLO 只回答“图像中哪里有棋子”，不负责选择目标、规划推扫或控制底盘。
3. **全局坐标统一：** 棋子、机器人、场地、得分区和推扫任务统一使用场地坐标系，单位 mm。
4. **闭环而非开环：** 每次推扫后重新观测、更新地图、验证结果，再决定下一步；不假设棋子会随车体按相同距离移动。
5. **实时控制不等待推理：** 相机、YOLO、任务规划和底盘控制解耦；推理慢时丢弃过期帧，只消费最新有效观测。
6. **仿真真值隔离：** 仿真真值只用于标注、离线评价和验收，不得进入机器人运行时决策输入。
7. **仿真与实车共用上层逻辑：** 通过相机、定位、底盘和时钟适配接口隔离平台差异。

## 2. 场地与坐标约定

依据场地尺寸沟通图（3000 × 2000 mm）：

- 原点：场地左下角；
- X 轴：向右；
- Y 轴：向上；
- 场地边界：\(0 \le x \le 3000\)，\(0 \le y \le 2000\)；
- 四周实体挡板高度：80 mm（以实际场地复核为准）。

区域配置：

| 区域 | 左下角 (mm) | 尺寸 (mm) |
|---|---:|---:|
| 甲队发车区 | (0, 0) | 610 × 420 |
| 乙队发车区 | (2350, 1580) | 650 × 420 |
| 棋子堆放区 | (1200, 740) | 600 × 530 |
| 甲队球门区 | (0, 420) | 110 × 1150 |
| 乙队球门区 | (2890, 420) | 110 × 1150 |

己方得分区通过配置选择，不在代码中散布甲乙队硬编码。球门区域的几何范围不等于已经确认的实体入口结构；实现前需以仿真模型和实际场地确认入口是否贯通、门框及挡板的真实碰撞边界。

## 3. 六层系统架构

### L1 — 视觉感知层（唯一神经网络）

**输入：** 带采集时间戳的前视 RGB 图像。  
**处理：** 单类 YOLO 检测，类别统一为 `piece`。  
**输出：** 检测框、置信度、图像接地点估计、图像时间戳。

建议使用检测框底边中心作为棋子接地点的初始估计：

\[
u_f=(x_1+x_2)/2, \qquad v_f=y_2
\]

如棋子倾斜、遮挡或检测框底边不稳定，可在不增加神经网络的前提下，评估传统轮廓/分割方法作为局部修正；第一版先使用统一的底边中心定义。

不做棋种、红黑方或棋面分类，因为当前集棋目标不依赖这些信息。

### L2 — 坐标转换与世界模型层

将图像接地点转换为场地坐标：

1. 使用已有相机标定参数处理畸变（若输入图像已经去畸变，不得重复去畸变）。
2. 利用已标定的相机相对车体外参和地面平面模型，将接地点投影到车体坐标系地面。
3. 利用图像采集时刻对应的机器人位姿，将车体坐标转换到场地坐标。
4. 保存坐标、置信度、观测时间和不确定度。

平面地面投影可用已标定的单应矩阵，或相机射线与地面平面求交。具体采用哪一种，以现有标定产物为准；不得重新猜测或覆盖已验证参数。

坐标变换形式：

\[
P_w = P_r(t_i) + R(\theta_r(t_i))P_c
\]

其中 \(t_i\) 是图像采集时刻，必须使用与图像时间戳对齐或插值得到的机器人位姿，不能直接使用推理结束时的最新位姿。

世界模型维护：

- 静态场地地图、边界、挡板和得分区；
- 机器人位姿、朝向和运动状态；
- 棋子轨迹及状态；
- 已观测区域/未观测区域；
- 当前推扫任务及任务历史。

棋子状态建议：

`UNSEEN → DETECTED → TRACKED → IN_PUSH_GROUP → PUSHING → TRACKED / SCORED`

暂时无法观测时标记为 `LOST`，不能因离开相机视野就标记为 `SCORED`。只有得分区内的视觉确认或仿真裁判侧的独立验收记录，才能确认得分；裁判真值不得反馈给运行时策略。

数据关联第一版采用门限最近邻；出现密集交叉、多个候选冲突时再使用匈牙利算法。卡尔曼滤波用于平滑观测，不应把正在被推的棋子错误地当成静止目标。

### L3 — 策略决策层

分为三个任务阶段：

**A. 搜索与建图**

- 根据相机视场、机器人位姿和已扫描区域，生成未观测区域。
- 优先扫描可能存在棋子的区域，包括中央活动区、边缘区域及球门附近。
- 每次移动后用新图像更新覆盖地图。
- 不假设前视相机能一次看到整个场地。

**B. 集中推扫**

- 对已观测棋子进行空间聚类。DBSCAN 可作为第一版候选算法，参数应依据棋子直径、间距分布和推板尺寸实测设定。
- 对每个棋子簇生成多个候选推扫方向和终点。
- 评估推板覆盖范围、接近可达性、车体转弯约束、边界风险、球门入口拥堵和预计送入数量。
- 对候选任务计算代价并选择当前最合适任务，不追求一次性规划 32 枚棋子的固定路线。

候选任务代价可采用：

\[
J = w_d C_{travel}+w_a C_{align}+w_r C_{risk}
  +w_g C_{goal}-w_n N_{expected}
\]

其中各项均需归一化；权重通过仿真配对实验调整。\(N_{expected}\) 是预计能送入得分区的棋子数，不等同于实际得分数。

**C. 精细清理**

- 当剩余棋子较少，或大范围推扫收益下降时，切换到单枚/小簇任务。
- 优先处理边缘、墙边、球门附近和前序推扫遗漏的棋子。
- 对无法安全接近的目标，重新选择接近方向或暂缓，不应无限重复同一失败动作。

### L4 — 运动规划层

将任务转换为机器人可执行的接近位姿和推扫轨迹。

若推扫方向单位向量为 \(d=(\cos\alpha,\sin\alpha)\)，接触点为 \(P_c\)，推板接触面相对车体中心的前向距离为 \(L\)，则近似接近位姿为：

\[
P_r=P_c-Ld, \qquad \theta_r=\alpha
\]

实际计算必须进一步考虑车体外形、推板宽度、推板偏置、棋子簇边界和碰撞安全余量。

规划分为：

- 空载导航：使用 A* 或 Hybrid A* 等考虑场地障碍和底盘运动学的算法；
- 接近：低速到达接近位姿，校正角度；
- 接触：缓慢前进，建立推板与目标棋子簇的接触；
- 推扫：沿受约束轨迹低速推进；
- 退出/恢复：停止、退开或调整方向，再重新感知。

不应在未确认底盘运动学前，假设小车能原地旋转或任意横移。差速、四轮差速、麦克纳姆和阿克曼底盘需要不同的可行轨迹约束。

### L5 — 执行控制层

底盘控制线程独立运行，不等待 YOLO 推理和高层任务规划。

- 空载运动采用现有底盘控制接口和轨迹跟踪器；
- 推扫运动采用低速直线/曲线跟踪及航向闭环；
- 视觉更新用于修正任务状态和必要时重规划；
- 推扫过程中按距离、时间或视野变化触发观测，不要求每个控制周期都运行 YOLO；
- 检测到卡滞、越界风险、位姿异常或任务超时，应先进入安全停止/恢复流程。

相机和 YOLO 采用异步生产者/消费者模式。队列只保留最新帧，附带采集时间戳；旧帧超过允许时延后直接丢弃。控制周期和 YOLO 帧率根据实际树莓派 5 测量值确定，不在算法中写死未经验证的 FPS 承诺。

### L6 — 结果验证与恢复层

每次推扫结束：

1. 停止底盘并等待必要的物理稳定时间；
2. 获取新鲜图像并运行 YOLO；
3. 更新棋子地图和轨迹；
4. 检查目标簇是否仍在场内、是否分散、是否进入球门；
5. 估计本次任务的实际净得分变化；
6. 选择下一项任务或执行恢复。

恢复策略：

| 异常 | 处理 |
|---|---|
| 棋子未移动 | 重新估计接触点，调整对齐/接近方向 |
| 棋子被推散 | 重新检测、关联、聚类，生成补扫任务 |
| 棋子到达边界 | 沿可行方向规划边界恢复动作 |
| 球门入口拥堵 | 拆分目标簇，分批输送 |
| 目标暂时丢失 | 到安全观察位重新观测，不推测其已得分 |
| 接近路径不可行 | 更换接近方向或选择其他任务 |
| 推扫中断/卡滞 | 停车、评估状态，再执行有界恢复 |

任务终止条件应同时考虑比赛时间、已确认得分数、剩余候选和安全状态。若规则要求收集全部棋子，可将 32 枚全部确认得分设为理想完成条件；不能把“检测不到剩余棋子”作为完成条件。

## 4. 运行时数据流与线程模型

推荐逻辑数据流：

`Camera → Frame(timestamp) → YOLO → Detections → Coordinate Transform → World Model → Task Planner → Motion Planner → Controller`

控制反馈：

`Robot Pose / Controller Feedback → World Model`

推扫后验证：

`New Frame → YOLO → World Model Update → Score/Recovery Decision`

线程/进程职责：

| 工作单元 | 职责 | 约束 |
|---|---|---|
| Camera worker | 采集图像并打时间戳 | 不积压旧帧 |
| YOLO worker | 单类检测 | 只消费最新可用帧 |
| State estimator | 坐标转换、位姿时间对齐、数据关联 | 不使用未来位姿或仿真真值 |
| Planner | 搜索、聚类、任务选择、轨迹生成 | 低频运行，避免阻塞控制 |
| Controller | 底盘闭环控制 | 固定周期，独立运行 |
| Evaluator/logger | 记录检测、任务、得分和时延 | 记录不影响实时控制 |

各模块以明确的数据结构通信，至少包含时间戳、坐标系标识、置信度和数据有效性。

## 6. 状态机

建议顶层行为状态：

```text
INITIALIZE
  → OBSERVE
  → UPDATE_WORLD
  → SELECT_TASK
  → PLAN_APPROACH
  → NAVIGATE
  → ALIGN
  → CONTACT
  → PUSH
  → VERIFY
      ├─ 成功/状态已知 → OBSERVE
      ├─ 可恢复失败 → RECOVER → OBSERVE
      └─ 无可行任务 → SEARCH / SAFE_STOP
```

任何状态都应能响应安全停止。状态切换必须有明确的进入条件、退出条件、超时和失败原因，避免无限重试。

## 7. 分阶段实施路线

### 阶段 1：YOLO 到场地坐标

- [ ] 复用当前单类 YOLO 权重和推理接口；
- [ ] 确认图像是否已去畸变，防止重复处理；
- [ ] 使用已有相机标定和地面投影参数；
- [ ] 按图像采集时间戳匹配机器人位姿；
- [ ] 在仿真中对照真值，统计位置误差（真值只用于离线评价）。

**验收：** 不同机器人位置和朝向下，图像检测均能转换到统一场地坐标；报告误差分布和失败场景。

### 阶段 2：动态世界模型

- [ ] 实现棋子数据结构、ID、数据关联和状态管理；
- [ ] 实现重复检测、短时遮挡、出画后重现处理；
- [ ] 实现已观测区域覆盖图；
- [ ] 区分静止、正在推送和暂时丢失的棋子。

**验收：** 小车移动和相机视角变化后，地图不因重复观测而重复计数；丢失目标不会被错误标记为得分。

### 阶段 3：自主单棋闭环

- [ ] 从世界模型自动选择一枚目标棋子；
- [ ] 计算可行接近位姿；
- [ ] 自主导航、对齐、接触和推送；
- [ ] 推送后重新观测并验证棋子状态；
- [ ] 对失败原因进行分类并记录。

**验收：** 随机起始位姿和目标位置下，不人工指定棋子坐标或推送轨迹，能够完成自主选择与单棋推送；统计成功率、碰撞和耗时。

### 阶段 4：多棋子聚类与推扫

- [ ] 实现聚类和孤立棋子识别；
- [ ] 生成多个候选推扫方向；
- [ ] 评估推板覆盖、接近可达性和边界风险；
- [ ] 执行分段推扫并在推后更新地图；
- [ ] 与逐枚推送基线做同布局配对实验。

**验收：** 多棋子推扫在冻结测试布局中能产生可重复的净得分收益，且不以更多碰撞或更高零分率换取局部收益。

### 阶段 5：全场搜索与自主集棋

- [ ] 扫描未知区域并维护覆盖地图；
- [ ] 实现中央区、边缘区和球门入口的任务调度；
- [ ] 实现集中推扫与精细清理切换；
- [ ] 实现球门入口分批输送；
- [ ] 实现有界恢复和任务终止逻辑；
- [ ] 对随机 32 棋布局进行完整限时盲测。

**验收：** 运行时仅使用规定的 RGB、机器人位姿、时钟和静态配置；随机 32 棋盲测报告净得分、零分局比例、首枚得分时间、平均得分、碰撞、耗时和失败分类。

### 阶段 6：性能优化与实车迁移

- [ ] 在目标树莓派 5 上测量端到端推理延迟、P50/P95、FPS 和 CPU 占用；
- [ ] 对比输入尺寸、线程数和模型导出格式对召回率及时延的影响；
- [ ] 根据时延测量确定观测触发频率和允许的最大观测年龄；
- [ ] 先仿真回放，再进行受控实车测试；
- [ ] 验证长时间运行、相机断流、位姿异常和安全停止。

**验收：** 给出实际板端数据和实车证据；未实测的指标不得标记通过。

## 8. 评价指标与实验协议

每局至少记录：

- 初始棋子数、最终确认得分数、终局剩余数；
- 检测 Precision / Recall（使用独立标注集）；
- 棋子场地坐标误差的均值、P95；
- 地图重复计数、漏跟踪和错误得分次数；
- 单次推扫接触数、实际净得分变化和成功率；
- 空载距离、推扫距离、任务数和恢复次数；
- 首枚得分时间、总完成时间、零分局比例；
- YOLO FPS、图像年龄、推理延迟 P50/P95、CPU/内存占用；
- 碰撞、卡滞、越界和安全停止次数。

实验要求：

1. 使用冻结随机种子和独立盲测布局；
2. 候选方案与基线使用相同布局、时间预算和计分方式；
3. 开发集结果不能代替盲测结果；
4. 仿真真值只用于离线评估；
5. 同时报告平均值、离散程度和失败局，不能只展示最好的一局；
6. 每次策略变更记录代码版本、配置、权重和实验种子。

## 9. 关键风险与待实测参数
